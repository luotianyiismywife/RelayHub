## J. 计费与用量维度（2026-08-22 全网调研新增）⭐ 重大遗漏

> 调研 OpenRouter / LiteLLM / Helicone / Langfuse / New API / one-api / Higress 的价格体系后，发现当前设计（Balance/Usage 窗口/峰谷）**只覆盖了很小一部分**。
> 真正的成本计算是**多维度**的：不同 token 类型费率不同、缓存/推理/图片/音频/视频单独计价、长上下文分档、时间窗条件倍率、流式预扣结算。
> 这些几乎全是 `Kernel-billing` 的职责（上游插件只返回平台数据，不做成本计算）。

| # | 待办 | 说明 | 参考实现 | 状态 |
|---|---|---|---|---|
| J1 | **Token 多维度分类计费** ⭐最大遗漏 | 输入/输出/缓存读/缓存写(5m+1h)/推理/图片输入/图片输出/音频输入/音频输出/视频/工具调用 —— **每维独立费率**，成本 = Σ(各维 token × 各维单价)；契约见 [插件模板分类 §0.6](./02-插件体系/插件模板分类.md)（TokenUsage/PriceTable） | **new-api `TokenParams` 10 维**（P/C/Len/CR/CC/CC1h/Img/ImgO/AI/AO）、OpenRouter 15 维、LiteLLM | ⬜ 契约✅ 已落 |
| J2 | **缓存定价（prompt caching）** | cache read（命中读，约 1/10 价）vs cache write（写入创建，约 1.25x）；**Claude 5min/1h TTL 两种 cache write**；流式响应提取 cached_tokens —— **convert_response 归一化已入模板**（extract_usage） | OpenRouter/LiteLLM/Helicone、Higress ai-statistics（`cached_tokens`） | ⬜ 契约✅ 已落 |
| J3 | **阶梯/长上下文定价（tiered）** | 输入 token 超阈值 → 换费率（如 >1M 上下文更贵）；请求跨越档位 → 分段计价 | OpenRouter `min_prompt_tokens`、LiteLLM `*_above_<N>_tokens`、new-api `tier()` | ⬜ |
| J4 | **条件倍率规则（峰谷泛化）** | 峰谷 PeakRate 泛化成**条件规则**：时间窗（utc_start/end）+ 请求头/星期/小时/月条件 → 倍率；当前仅 PeakRate（时段）不够 | OpenRouter `PricingOverride`、new-api billingexpr（header/hour/weekday 条件） | ⬜ |
| J5 | **预扣/结算两阶段** ⭐流式关键 | 流式请求先按 prompt 估算**预扣** quota → 响应完成后按实际 usage **回填 diff**；流式中断/取消回滚；可信用户免预扣；余额<预扣阈值时拒 | **one-api `preConsumeQuota`/`postConsumeQuota`**（relay/controller/helper.go） | ⬜ |
| J6 | **特殊单位计费** | 不是所有模型按 token：realtime 音频按**秒**、图片生成按**张**、视频按秒、web search 按请求 | LiteLLM `audio second`/`output_cost_per_image`、new-api realtime 按秒 | ⬜ |
| J7 | **统一价格表** | 模型多维价格 JSON（litellm 那套），Kernel-billing 消费；自用可裁剪子集 | litellm `model_prices_and_context_window.json` | ⬜ |
| J8 | **服务层（service tier）** | priority（贵/快）vs flex（便宜/弹性）两个档位 | LiteLLM `*_priority`/`*_flex` | ⬜ 未来 |
| J9 | **缺失值语义** | unknown vs explicit 0 必须区分（不能把未知伪装成免费）；`-1` sentinel 不可当费率 | all-api-hub 调研结论 | ⬜ |
| J10 | **批处理折扣（batch）** | batch API 独立费率（OpenRouter 独立 `:batch` 模型变体）；异步批处理计费 | OpenRouter `:batch` 变体 | ⬜ 未来 |
| J11 | **用量明细 token 细分** | `Kernel-usage`（H2）应记录 `input_token_details`/`output_token_details`（含 reasoning/cached/工具），不只是总数 —— **上游插件侧已落**：convert_response 的 extract_usage 归一化（模板+3 示例）；内核侧 Kernel-usage 待写 | Higress ai-statistics（内置属性 JSON 对象） | ⬜ 上游✅ 已落 |
| J12 | **货币/单位换算** | quota 单位体系（new-api：USD=500，USD2RMB=7.3）；Kernel-billing 的成本换算（美元→人民币→quota） | new-api `USD2RMB`/`USD` 常量 | ⬜ |

**与现有设计的关系**：
- J1-J4、J6-J10、J12 = `Kernel-billing`（成本计算）的维度扩展 —— 上游插件仍然只返回平台数据（Balance/Usage），**多维费率在价格表（J7）+ 内核计算**
- J5 = 内核转发引擎的 quota 处理（防流式跑飞）
- J11 = `Kernel-usage`（H2）的记录字段扩展
- **峰谷 PeakRate 是 J4 的一个特例**：PeakRate = 固定时段条件，J4 = 任意条件（时间/头/星期）
- **已落地**：J1/J2/J11 的**上游插件侧**（TokenUsage 契约 §0.6 + convert_response 的 extract_usage 已写进模板和 3 个示例）；**内核侧**（Kernel-billing 计算/预扣结算）待 D 组后写
