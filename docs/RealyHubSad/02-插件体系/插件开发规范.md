# 插件开发规范

> 插件开发者的规范总纲。所有 RelayHub 插件（内核/页面/上游）必须遵守。
> 关联：[插件体系总览](./插件体系总览.md)（三类插件）/ [插件模板分类](./插件模板分类.md)（kind）/ [上游定义声明化设计](./上游插件/上游定义声明化设计.md)（yaml 契约）

---

## 1. 插件名规范（硬性约束）

> 用户 2026-08-21 确认：**插件名不用 `_`，用 `-`**。

### 1.1 为什么

对外模型名格式为 `<上游名>_<模型名>`，`_` 是**独占分隔符**：

- 插件名含 `_` → 前缀拆解歧义（`foo_bar_模型` 的插件是 `foo_bar` 还是 `foo`？）
- 模型名规范化后 `_`→`-`，插件名再用 `-` → 两侧都不含 `_`，`_` 唯一且安全

### 1.2 规则

| 项 | 规范 | 例子 |
|---|---|---|
| 插件名 | 用 `-`，**禁止用 `_`** | `opencode-go` ✅ / `opencode_go` ❌ |
| 目录名 | 与插件名一致 | `opencode-go/` |
| 版本目录 | `<插件名>-<版本>` | `opencode-go-1.0.0/` |
| metadata.name | 与插件名一致 | `name: opencode-go` |
| package.json name | 与插件名一致 | `"name": "opencode-go"` |

### 1.3 命名建议

- 用平台/项目真实名（`opencode-go`、`tokenrhythm`、`one-api`）
- 全小写（待定：大小写保留规则见模型映射设计 §6）
- 简洁，无空格

### 1.4 版本号规范（Cargo / SemVer 规则）

> 用户 2026-08-22 拍板：**所有主体（内核 / 插件 / 上游定义）版本号统一按 Cargo 规则**。

**格式**：`MAJOR.MINOR.PATCH` 三级，可选预发布和构建元数据：

```
1.0.0          # 正式版
0.9.0          # 0.x 预发布语义（不稳定，同 minor 内可 breaking）
1.2.3-alpha.1  # 预发布（alpha/beta/rc）
1.2.3+build.7  # 构建元数据（不参与版本比较）
```

| 规则 | 说明 |
|---|---|
| 版本号 | 三级 `MAJOR.MINOR.PATCH`，与目录名 `<插件名>-<版本>` 一致 |
| 预发布 | `-alpha.N` / `-beta.N` / `-rc.N`，**不参与常规依赖解析**（需显式指定） |
| 构建元数据 | `+build`，仅标识，不影响版本优先级 |
| 0.x 语义 | `0.1`→`0.2` 视为 breaking（Cargo 对 0.x 的特殊规则） |
| 升级规则 | breaking → MAJOR+1；加功能向后兼容 → MINOR+1；修 bug → PATCH+1 |

**版本约束符号**（依赖声明用，Cargo VersionReq 语义）：

| 约束 | 含义 |
|---|---|
| `^1.2.3` | `>=1.2.3, <2.0.0`（默认；`^0.2` → `<0.3`） |
| `~1.2.3` | `>=1.2.3, <1.3.0`（只允许 patch 更新） |
| `=1.2.3` | 精确版本 |
| `>=1.2, <2.0` | 区间 |
| `1.*` / `*` | 通配 / 任意 |

## 1.5 插件依赖声明（Cargo.toml `[dependencies]` 风格）

> 用户 2026-08-22：插件依赖参考 Cargo 规则。

```yaml
# upstream.yaml / <插件名>-<版本>/upstream.yaml 根级段
# （目录式结构：<插件名>-<版本>/ 内含 upstream.yaml，见 §2）
depends:
  kernel: "^0.1"          # ← 依赖内核 SDK（虚拟依赖，兼容契约）
  Kernel-billing: "~1.2"  # ← 依赖另一个插件（页面插件依赖内核插件产数据）
```

- **依赖名**：插件名（大小写敏感，与 kind 一致）或 `kernel`（内核 SDK）
- **约束**：Cargo 约束符号（见 §1.4 表）
- **Page → Kernel 依赖**：页面插件消费内核插件产出的标准数据时，靠 `depends` 声明（B2 细化）
- **解析规则**：同 major 兼容；diamond 冲突（两插件依赖不兼容版本）→ 启动报错；实际解析版本记入 `relayhub.lock`（I4/I5）

## 2. 目录结构规范

```
plugin/
├── Example/                          # 示例插件（可运行参考）
│   └── UpStream/
│       └── Api/
│           ├── tokenrhythm/tokenrhythm-1.0.0/
│           ├── opencode-go/opencode-go-1.0.0/
│           └── one-api/one-api-1.0.0/
└── Template/                         # 模板插件（复制改名使用）
    └── UpStream/
        └── Api/
            └── example-plugin/example-plugin-1.0.0/
```

**插件包内部**（版本目录下）：

```
<插件名>-1.0.0/
├── upstream.yaml      # 上游定义（kind/apis/auth/special/protocols/scripts/depends）
├── http.yaml          # 状态码 → 动作映射（rotate/cooldown/retry/passthrough）
├── models.yaml        # 模型列表声明/缓存（由 models.ts 生成，内核读取）★ 2026-08-24 新增
├── convert.ts         # convert_request / convert_response（参数修正 + usage 归一化）
├── models.ts          # list_models（模型列表归一化 + _→- 转换，生成 models.yaml）
├── quota.ts           # quota_balance / quota_usage（计费查询）
├── package.json       # 元数据（name/version/dependencies）
└── README.md          # 平台说明（可选）
```

> 文件组织**自由**：简单插件可一个文件，复杂插件可拆多个，yaml 的 `scripts` 映射决定调用。

## 3. 文件命名规范

| 文件 | 用途 | 建议拆分 |
|---|---|---|
| `upstream.yaml` | 上游定义（唯一必需文件） | 不拆 |
| `http.yaml` | 状态码 → 动作映射（rotate/cooldown/retry/passthrough，判定在插件） | 不拆 |
| `models.yaml` | 模型列表声明/缓存（由 models.ts 生成，内核读取，勿手改）★ 2026-08-24 | 不拆 |
| `convert.ts` | 协议参数修正 + usage 归一化（不做格式转换） | convert_request / convert_response / extract_usage |
| `models.ts` | 模型列表（list_models：拉取 + _→- 归一化 + 返回 ModelInfo[]） | list_models |
| `quota.ts` | 计费查询 | quota_balance / quota_usage |
| `auth.ts` | 凭据相关（sub 类） | refresh_credentials / validate_credential |

> `.ts` 源码 → 构建时编译成 `.js`（QuickJS 方案）或直接跑（deno_core 方案）。

## 4. 钩子命名规范

| 钩子 | 必配 | 说明 |
|---|---|---|
| `list_models` | ✅ 默认必配 | 模型列表归一化（各平台大概率不同） |
| `quota_balance` | kind=balance | 余额查询（纯数字，无货币符号） |
| `quota_usage` | kind=quota | 套餐限额查询（多窗口） |
| `convert_request` | 可选 | 协议条件修正（有怪癖才写） |
| `convert_response` | 可选 | 响应修正 |
| `refresh_credentials` | sub 类 | 凭据刷新（逻辑在 ts，调度在内核） |
| `validate_credential` | sub 类 | 账号有效性验证 |

**钩子→文件映射**（yaml 声明，不猜目录结构）：
```yaml
scripts:
  list_models:   ./models.ts    # 函数名 = 钩子名（默认）
  quota_balance: ./quota.ts
  convert_request: { file: ./convert.ts, fn: convertRequest }  # 或指定函数名
```

## 5. 其他开发约定（汇总）

1. **静态进 yaml，条件进 ts**：静态强制头/必传字段放 `special`，条件逻辑才写 ts
2. **上游插件只拿数据**：余额/用量返回平台原样数字，成本计算/货币转换归内核
3. **协议名 = apis key**：`openai` / `anthropic` / `responses` / `gemini`（四协议内核内置，其他用 ts）
4. **凭据只写引用**：`credentials: ref:<插件名>-prod`，值由 docker secret 提供
5. **版本管理（Cargo/SemVer）**：目录名 `-<版本>` + metadata.version + package.json 三者一致；版本号与约束符号见 §1.4；依赖用 `depends` 声明（§1.5）
6. **平台实测规则**：写进插件 README（如 tokenrhythm 的踩坑记录），便于后续维护

## 6. 职责边界（三类插件各写什么，2026-08-22 用户拍板）

> **原则：上游插件 = 平台说明书（数据/协议/怪癖）；内核插件 = 横切能力；内核 = 转发引擎。**
> 写插件时照着下表对号入座，**不用想哪些没法和内核对接** —— 表里没写到的都是内核/内核插件的事。

### 6.1 上游插件（Upstream-*）

| 能力 | 写哪 | 说明 |
|---|---|---|
| 端点/协议 | `apis` | 四协议内核内置，其他用 ts |
| 鉴权 | `auth` | 转发 key + `auth.query` 查询凭据分离 |
| 静态规则 | `special` | 强制头/必传字段/透传剥离 |
| 模型列表 | `models.ts` `list_models` | 返回 ModelInfo[]（含 capabilities） |
| 模型映射 | `model_map` | **数据在插件**（行为在内核 ModelResolver） |
| 协议修正 | `convert.ts` | 条件逻辑（thinking 限制/工具格式差异等） |
| 余额/套餐 | `quota.ts` | 返回平台原始数据（细分/窗口/峰谷） |
| 错误判定 | `rotation` | http_rules（http.yaml 状态码→动作）/ error_patterns / balance_ttl |
| usage 明细 | `convert_response` extract_usage | 归一化 TokenUsage 透传给内核 |

**❌ 上游插件绝不写**：成本计算、预扣结算、限流、重试、缓存、日志、告警、健康检查、模型元数据合并。

### 6.2 内核插件（Kernel-*）

| 能力 | 插件 | 说明 |
|---|---|---|
| 成本计算 | `Kernel-billing` | 价格表 + 多维费率 + 阶梯 + 换算（J 组） |
| 日志/审计 | `Kernel-logging` | 每轮请求/返回完整记录 |
| 用量统计 | `Kernel-usage` | key × 渠道 × 模型 token 明细 |
| 健康检查 | `Kernel-health` | 熔断/半开/自动下线 |
| 重试/回退 | `Kernel-retry` | 指数退避 + fallback |
| 限流/并发 | `Kernel-ratelimit` | 按用户/模型/全局 + 并发上限 |
| 缓存 | `Kernel-cache` | 语义缓存 |
| 告警 | `Kernel-alert` | 判定 + Page-alert 通知 |
| 审计 | `Kernel-audit` | 内容检查（默认关） |
| 预算 | `Kernel-budget` | 虚拟 key 预算上限 |

### 6.3 内核（转发引擎）

凭据托管（docker secret）、协议入口转换、路由/调度、预扣/结算（J5）、TTL 缓存、插件加载（I 组）、热重载。

> **完整对照见模板 `Template/UpStream/Api/example-plugin/README.md`「职责边界」表 + 模板分类 §0.5「对号入座表」**。
